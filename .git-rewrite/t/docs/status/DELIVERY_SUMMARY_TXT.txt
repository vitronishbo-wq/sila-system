🔄 RETRY STRATEGY
   Tentativa 1: Imediato
   Tentativa 2: 0.5s + jitter
   Tentativa 3: 1.0s + jitter

⚙️  CONFIGURAÇÃO (YAML FILES)

📋 ci/endpoints.yaml
   Define 17 endpoints para testar:
   - Health check
   - Auth endpoints (login, logout)
   - User endpoints (profile, etc)
   - API endpoints
   - CORS preflight tests

📋 ci/backend_context.yaml
   Configuração centralizada:
   - backend.base_url, timeout, max_retries
   - auth: method (static/command), token, command
   - cors: enabled, allowed_origins
   - sla: p95_latency_ms, p99_latency_ms

📋 .github/workflows/integration-tests.yaml
   CI/CD automation:
   - Triggers: push, PR, schedule (hourly)
   - Setup: Python, DB, Backend, Frontend
   - Executa: validation, parse results, PR comment
   - Upload: artifacts, logs
   - Alert: Slack (opcional)


🔄 EXEMPLOS DE USO
═══════════════════════════════════════════════════════════════════════════════

# Teste padrão
python scripts/validate_frontend_backend_integration.py

# Com configuração
python scripts/validate_frontend_backend_integration.py \
  --context ci/backend_context.yaml \
  --endpoints ci/endpoints.yaml

# Com autenticação dinâmica
python scripts/validate_frontend_backend_integration.py \
  --auth-command "./scripts/get_dev_token.sh"

# Staging environment
python scripts/validate_frontend_backend_integration.py \
  --backend-url "https://api-staging.sila.gov.ao" \
  --frontend-url "https://app-staging.sila.gov.ao"

# Apenas JSON output
python scripts/validate_frontend_backend_integration.py \
  --format json

# Dry-run (teste sem falhar)
python scripts/validate_frontend_backend_integration.py --dry-run

# Ver todas as opções
python scripts/validate_frontend_backend_integration.py --help
